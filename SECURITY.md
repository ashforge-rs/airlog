# Security Policy

## Supported Versions

Only the latest release of **airlog** receives security fixes.

| Version | Supported |
|---------|-----------|
| Latest  | ✅        |
| Older   | ❌        |

## Reporting a Vulnerability

**Please do not open a public GitHub issue for security vulnerabilities.**

If you discover a security issue, report it privately through one of the following channels:

1. **GitHub Private Security Advisory** *(preferred)*:
   Navigate to the [Security tab](../../security/advisories/new) of this repository and click **"Report a vulnerability"**.

2. **Email**: If you prefer e-mail, contact the maintainers at the address listed in `pyproject.toml`.

### What to include

Please provide as much of the following information as possible to help us triage and resolve the issue quickly:

- A description of the vulnerability and its potential impact
- Steps to reproduce or a minimal proof-of-concept
- Affected version(s)
- Any suggested mitigations you are aware of

### Response timeline

| Milestone                    | Target       |
|------------------------------|--------------|
| Initial acknowledgement      | ≤ 3 business days |
| Triage and severity rating   | ≤ 7 days     |
| Patch or mitigation released | Depends on severity |

We will keep you informed of progress throughout the process and credit you in the release notes (unless you prefer to remain anonymous).

## Disclosure Policy

We follow a **coordinated disclosure** model.  Once a fix is ready and released, we will publish a GitHub Security Advisory with full details.  We ask that you give us a reasonable window (up to 90 days) to prepare and release a fix before public disclosure.
